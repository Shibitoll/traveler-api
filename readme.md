# Traveler API — RESTful Web Service

**Traveler API** — це RESTful веб-сервіс для планування подорожей та керування локаціями, розроблений на фреймворку **Spring Boot 3** з використанням **Java 21**. Сервіс підтримує надійний захист від конфліктів паралельного доступу (Race Conditions) за допомогою версіонування та оптимістичного блокування (**Optimistic Locking**).

---

##  Основні можливості

*  **Управління плануванням подорожей (Travel Plans):** створення, оновлення, перегляд та видалення планів із кастомними валютами, бюджетом та публічним доступом.
*  **Управління локаціями (Locations):** додавання локацій до планів, розрахунок порядкового номера візиту (`visit_order`), координатами та датами прибуття/вибуття.
*  **Захист від конфліктів паралельного доступу:**

  * Оптимістичне блокування планів через JPA анотацію `@Version`.
  * Каскадне версіонування локацій через `parent_version` з поверненням HTTP статус-коду `409 Conflict`.
*  **Автоматична Swagger/OpenAPI документація:** інтерактивний Swagger UI для перегляду схем та тестування ендпоінтів.
*  **Строга валідація даних:** перевірка географічних координат, дат, бюджетів та валідності ISO-кодів валют із форматованими помилками `400 Bad Request`.

##  Архітектура REST API

###  Travel Plans (`/api/travel-plans`)

| Метод    | Ендпоінт                 | Опис                                         | Очікуваний код             |
| :------- | :----------------------- | :------------------------------------------- | :------------------------- |
| `GET`    | `/api/travel-plans`      | Отримати список усіх планів (Summary DTO)    | `200 OK`                   |
| `POST`   | `/api/travel-plans`      | Створити новий план подорожі                 | `201 Created`              |
| `GET`    | `/api/travel-plans/{id}` | Отримати деталі плану з усіма локаціями      | `200 OK` / `404 Not Found` |
| `PUT`    | `/api/travel-plans/{id}` | Оновити існуючий план подорожі               | `200 OK` / `409 Conflict`  |
| `DELETE` | `/api/travel-plans/{id}` | Видалити план за ID (з перевіркою `version`) | `204 No Content`           |

###  Locations (`/api`)

| Метод    | Ендпоінт                               | Опис                                             | Очікуваний код            |
| :------- | :------------------------------------- | :----------------------------------------------- | :------------------------ |
| `POST`   | `/api/travel-plans/{planId}/locations` | Додати нову локацію до плану                     | `201 Created`             |
| `PUT`    | `/api/locations/{id}`                  | Оновити існуючу локацію                          | `200 OK` / `409 Conflict` |
| `DELETE` | `/api/locations/{id}`                  | Видалити локацію (з перевіркою `parent_version`) | `204 No Content`          |

## 🏎 Вирішення проблем паралельного доступу

Сервіс гарантує цілісність даних при паралельній роботі декількох користувачів:

1. **Concurrent Plan Updates:** спроба зберегти застарілі дані плану відхиляється статусом `409 Conflict` завдяки JPA `@Version`.
2. **Sequential Location Addition:** додавання локації перевіряє та піднімає `version` батьківського плану, запобігаючи однаковим порядковим номерам (`visit_order`).
3. **Concurrent Location Updates:** будь-яка зміна локації вимагає збігу `parent_version` з актуальною версією плану подорожі.

##  Швидкий запуск

### Передумови

* Встановлений **JDK 21**
* Запущений сервер **PostgreSQL** (база даних `traveler_db`)

### Кроки для запуску

1. **Клонуйте репозиторій:**

   ```bash
   git clone https://github.com/Shibitoll/traveler-api.git
   cd traveler-api
   ```

2. **Налаштуйте змінні оточення:** створіть файл `.env` на основі `.env.example`:

   ```bash
   cp .env.example .env
   ```

   Вкажіть у `.env` ваші параметри підключення до PostgreSQL.

3. **Запустіть додаток:**

   ```bash
   ./mvnw spring-boot:run
   ```

4. **Відкрийте Swagger UI у браузері:** http://localhost:4567/swagger-ui/index.html
